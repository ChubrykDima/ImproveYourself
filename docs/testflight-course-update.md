# Обновление 30-дневного курса через TestFlight

Русский курс поставляется внутри приложения (`daily-challenges.ru.json`). Для его обновления нужен новый билд приложения. Существующий загруженный бинарник не редактируется, новое приложение в App Store Connect создавать не нужно.

## Что вошло в обновление

- Ровно 30 дней, с основным, облегчённым и необязательным усложнённым вариантом.
- Волнение и отказ не мешают засчитать собственное действие.
- День 17: просьба о поддержке; день 23: небольшое обещание себе.
- Повторение без обязательного усложнения; итог и самостоятельная практика на дне 30.
- Русский курс больше не заменяется старыми вращающимися шаблонами после стартовой самооценки. Выбор сложности пока текстовый: пользователь выполняет один вариант и отмечает обычный шаг как выполненный.
- Английский и немецкий курсы не менялись. Подписки и дни после 30 не добавлялись.

## Новый билд

1. Влить PR и получить актуальный `master`.
2. В App Store Connect → приложение → TestFlight проверить последний загруженный номер сборки. В проекте `ApplicationDisplayVersion` — публичная версия, `ApplicationVersion` — номер сборки. Для той же версии можно оставить `1.0`, но задать новый номер сборки выше уже загруженного. Если был `1`, следующий — `2`; не считать номер в исходниках подтверждением последнего номера в App Store Connect. Сохранить `ApplicationId`.
3. Использовать совместимые Xcode и .NET iOS workload. При проверке этого PR локальный SDK `26.5.10318` требовал Xcode `26.6`, а выбран был `27.0`; сборка остановилась до компиляции приложения. Не обходить эту проверку для релиза. Выбрать подходящий установленный Xcode либо согласованно обновить инструменты.
4. Собрать подписанный Release для `ios-arm64` привычным способом. Пример команды из корня репозитория (заменить номер сборки, сертификат и профиль своими значениями):

   ```sh
   dotnet publish ImproveYourself.Maui/ImproveYourself.Maui.csproj \
     -f net10.0-ios -c Release \
     -p:ArchiveOnBuild=true \
     -p:RuntimeIdentifier=ios-arm64 \
     -p:ApplicationDisplayVersion=1.0 \
     -p:ApplicationVersion=2 \
     -p:CodesignKey="Apple Distribution: YOUR NAME (TEAM ID)" \
     -p:CodesignProvision="YOUR APP STORE PROFILE"
   ```

5. Загрузить полученный `.ipa` через Transporter либо используемый процесс загрузки в App Store Connect. Дождаться обработки; при необходимости заполнить сведения об экспортном соответствии.
6. В TestFlight добавить новый билд в нужную группу тестировщиков и заполнить «Что тестировать». Для внешнего тестирования отправить на Beta App Review, если этого требует статус билда.
7. На iPhone открыть TestFlight и обновить приложение. Не удалять приложение ради обновления: это может удалить локальный прогресс.

## Что проверить на устройстве

- Обновить поверх предыдущего билда с уже выполненным днём и частично выполненным следующим. Проверить номер дня, отметки выполнения и статистику. Репозиторий при запуске обновляет тексты и восстанавливает статусы по прежним ID; переустановка не требуется. Тексты уже пройденных дней тоже могут обновиться.
- Выбрать русский язык, пройти стартовую самооценку: на первом дне должно остаться приветствие с вариантами сложности, а не старое случайное упражнение. Перезапустить приложение и проверить снова.
- Переключить язык с русского на другой и обратно: русский последовательный курс должен восстановиться, прогресс — сохраниться.
- Проверить переносы и прокрутку длинных карточек на небольшом iPhone и с увеличенным размером текста. Варианты сложности — альтернативы, а не три обязательных задания.
- Проверить дни 17, 23, 30; после завершения курса не должно появиться требования подписки, добавленного этим PR.

Проверки без iOS SDK: `dotnet run --project tests/ConfidenceCourse.Checks`.
Они проверяют структуру курса и доменную персонализацию; обновление SQLite и интерфейс на устройстве проверяются отдельно по списку выше.
